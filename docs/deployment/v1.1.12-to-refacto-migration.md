# OpenShift deploy delta: v1.1.12 → `refactor/hexagonal`

**Audience:** DevOps / platform team who already deploy OpenRAG **v1.1.12** on OpenShift and want to move to the `refactor/hexagonal` branch.
**Applies to:** base `v1.1.12` (Helm chart `charts/openrag-stack/`) → target `refactor/hexagonal` (Helm chart `infra/charts/openrag-stack/`).
**Status:** verified by diffing `infra/`, the Helm chart, and the env-var set between the two.

## Bottom line

Same topology, same Helm chart (relocated), **purely-additive env vars**, same UI. No re-architecture — mostly path/image repointing + chart re-validation. If v1.1.12 took weeks of OpenShift work, this should be **days**: the expensive integration (SCC, Routes/Ingress, PVCs, pull secrets, GPU scheduling, Milvus stack, Postgres) is reused.

## 1. Paths & image build (mechanical)

- [ ] **Helm chart moved**: `charts/openrag-stack/` → **`infra/charts/openrag-stack/`**. Repoint deploy scripts / CI.
- [ ] **App image**: root `Dockerfile` → **`infra/docker/api.Dockerfile`**; `Dockerfile.ray` → **`infra/docker/ray.Dockerfile`** (build context = **repo root**). Update image build + the chart's image repo/tag values.
- [ ] **Compose** (if used as a reference): root `docker-compose.yaml` → `infra/compose/docker-compose.yaml`.

## 2. Helm chart templates

- [ ] ⚠️ **`networkpolicy.yaml` was dropped** on refacto (present in v1.1.12, absent in refacto). If your OpenShift setup relied on it, re-add it or apply a NetworkPolicy out-of-band.
- [ ] All other templates are the same set, and **`values.yaml` top-level structure is unchanged** → existing values/overrides (SCC, routes/ingress, PVCs, pull secrets, resources) **carry over directly**.
- [ ] **UI unchanged**: refacto still ships the old `indexer-ui` (same image/template as v1.1.12). The new admin UI lives on a separate feature branch — **not** part of a refacto deploy, so no UI change to handle.

## 3. Env vars — non-breaking

- [ ] **0 removed, 0 renamed** → the entire v1.1.12 env file works as-is.
- [ ] **+16 new, all optional (have defaults)** — adopt only if needed:
  - `POSTGRES_DATABASE` — **use this** to set an explicit catalog DB name (eases the CREATEDB requirement; see "Postgres provisioning").
  - `POSTGRES_POOL_MIN_SIZE`, `POSTGRES_POOL_MAX_SIZE`, `POSTGRES_COMMAND_TIMEOUT` — connection tuning.
  - `EMBEDDER_BATCH_SIZE`, `EMBEDDER_CONCURRENCY`, `EMBEDDER_TIMEOUT` — embedder tuning (timeout/hang fixes on large PDFs).
  - `OPENRAG_MCP_*` (8 vars) — only if you enable the new MCP server (§4).

## 4. New optional component

- [ ] **MCP server** (Model Context Protocol) is new on refacto. Optional — deploy only if wanted; it needs its own service/port (`OPENRAG_MCP_HOST/PORT/PATH`, …). Skip otherwise.

## 5. Unchanged (knowledge transfers 1:1)

- Milvus + etcd + MinIO/S3; external model endpoints (LLM / VLM / embedder / reranker); Ray; PostgreSQL.
- Same open hardening items apply to **both** branches:
  - **Postgres provisioning**: the app auto-creates its database (needs `CREATEDB`) and runs schema creation at startup. On refacto, set `POSTGRES_DATABASE` to a **pre-created** database (OWNER = app role) so the role doesn't need `CREATEDB`.
  - **Storage**: the stack defaults to repo-tree bind mounts; on OpenShift use PVCs (configure in the chart values).

## 6. Caveat — branch stability

- [ ] `refactor/hexagonal` is an **untagged WIP branch**. Pin a specific commit (or wait for a tagged refacto release) rather than tracking `HEAD`.

## Effort summary

| Step | Rough effort |
|------|--------------|
| §1 repoint paths / images | ~½ day |
| §2 re-add networkpolicy + re-validate chart on OpenShift | 1–2 days |
| §3 env reconcile (optional vars) | hours |
| §4 MCP server (optional) | only if adopted |

Total: **days, not weeks** — assuming the chart behaves as it did on v1.1.12 (it's structurally the same).
