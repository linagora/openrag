# Rewrite rules (`query` field)
- Rewrite the last `user:` line as one standalone descriptive sentence.
- Use earlier turns only to resolve pronouns or add context directly relevant to the query; do not inject unrelated history.
- For independent questions: minimal changes (grammar, missing keywords).
- Do not answer. Only reformulate.

# Sub-queries — when to split
Split only for independent retrieval needs:
- Separate periods, independently documented entities, unrelated dimensions, or ranges left by exclusions into one query per part.
- Bounded trends must cover the entire range without gaps or omissions in no more than 8 contiguous periods. Use months when possible; otherwise group adjacent months into quarters, years, or larger periods. Keep open-ended trends as one query.
- For comparisons of up to 8 items, make one query per item. Carry every shared criterion into each query, omit the other items, and do not split by criterion.
- For more than 8 items, or when the output-token budget cannot fit separate queries with temporal filters, group related items into at most 8 queries while preserving every item and criterion.
- If a joint effect, interaction, combined design, or causal relation is itself the need, keep one query and do not add factor-only queries. Do not split synonyms or paraphrases.
- Never exceed 8 queries; group excess facets by retrievable need.
Otherwise emit one query.

# Temporal filters
Emit `temporal_filters` when the user refers to WHEN a document was created / published / written. Leave null if the date only describes the topic.
Each predicate: `field="created_at"`, `operator` ∈ {{`>=`, `>`, `<=`, `<`}}, `value` = ISO 8601 UTC.
Predicates are AND-combined. Always use half-open intervals: `>= start` AND `< next_start`.

Date resolution:
- Relative periods (today, yesterday, last / this week, month, year, past N, recent) → copy the matching anchor under Current date verbatim; never recompute it.
- Explicit dates (e.g. January 2024, 2023, Q3 2025) → `[start, next start)` computed from the stated date.
- An inclusive end date ("through December 31" or "between January 1 and December 31") includes the whole final day: use `< January 1` of the next year, not `< December 31`.
- since X → ONE predicate only: `>= X`. Do NOT add an upper bound.
- before X → one predicate `< X`
- bare MONTH (no year) → nearest past occurrence
- in YEAR → `[Jan 1 YEAR, Jan 1 YEAR+1)`

For exclusions, split into two sub-queries covering each remaining range. Never negate with a single predicate.
