Replace the nested httpx.Timeout construction at two locations in app_front.py:

**Location 1 (line 69 - auth_callback function):**
Change:
```python
async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=httpx.Timeout(4 * 60.0))) as client:
```


**Location 2 (line 134 - on_chat_start function):**
Change:
```python
async with httpx.AsyncClient(timeout=httpx.Timeout(timeout=httpx.Timeout(4 * 60.0))) as client:
```
To:
```python
async with httpx.AsyncClient(timeout=httpx.Timeout(4 * 60.0)) as client:
```

**Why this fix:** httpx.Timeout() accepts a float/int directly to set all timeout components (connect, read, write, pool) to the same value. Nesting Timeout objects creates a TypeError because the `timeout` parameter expects numeric values, not Timeout instances.

**Pattern from research:** The correct approach is `httpx.Timeout(240.0)` which applies a 4-minute timeout to all operations. Alternative granular control would be `httpx.Timeout(connect=5.0, read=240.0, write=240.0, pool=5.0)` if needed, but the simple form is sufficient here.
