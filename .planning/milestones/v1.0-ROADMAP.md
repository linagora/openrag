# Roadmap: OpenRAG Codebase Hardening (v1.0 Archive)

## Overview

This roadmap systematically addresses reliability and security issues across the OpenRAG codebase. Starting with isolated quick fixes, we progressively harden exception handling across API, core services, and pipeline layers. Then we address async infrastructure issues before hardening scripts and cleaning up configuration tech debt. Every fix maintains existing external API behavior and passes all 93 existing tests.

## Phases (All Complete)

### Phase 1: Quick Security Fixes (3/3 plans)
**Goal**: Fix isolated security issues and bugs that don't require architectural changes
- 01-01: Fixed nested httpx.Timeout bug in Chainlit frontend
- 01-02: Replaced unsafe PostgreSQL URL string interpolation with SQLAlchemy URL.create()
- 01-03: Added Pydantic schema validation for file upload metadata

### Phase 2: Exception Handling - API Layer (3/3 plans)
**Goal**: Replace broad exception handling with specific exception types in all API routers
- 02-01: Replaced 7 exception handlers in OpenAI router (streaming and non-streaming)
- 02-02: Replaced 5 exception handlers in indexer router (file ops and task management)
- 02-03: Replaced 6 exception handlers in tools, utils, actors, and extract routers

### Phase 3: Exception Handling - Core Services (4/4 plans)
**Goal**: Replace broad exception handling with specific exception types in components and pipeline
- 03-01: Replaced 17 exception handlers in vectordb and metadata operations
- 03-02: Replaced 10 exception handlers in indexer, embeddings, and chunker
- 03-03: Replaced 19 exception handlers in document loaders
- 03-04: Replaced 5 exception handlers in pipeline and LLM components

### Phase 4: Async Infrastructure (2/2 plans)
**Goal**: Eliminate blocking I/O operations in async contexts
- 04-01: Converted BaseLoader.save_content to async and restore script to async Ray calls
- 04-02: Converted blocking file I/O in 6 loaders to asyncio.to_thread

### Phase 5: Script & Health Hardening (2/2 plans)
**Goal**: Make restore script resilient to failures and improve health check observability
- 05-01: Enhanced health check with LLM/VLM service probes and response time metrics
- 05-02: Hardened restore script with rollback, progress tracking, and error summaries

### Phase 6: Configuration Cleanup (1/1 plan)
**Goal**: Remove technical debt from configuration and legacy compatibility code
- 06-01: Fixed Hydra version_base, added legacy prefix deprecation warning
