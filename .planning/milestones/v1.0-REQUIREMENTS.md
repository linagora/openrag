# Requirements: OpenRAG Codebase Hardening (v1.0 Archive)

**Defined:** 2026-02-10
**Completed:** 2026-02-11
**Core Value:** Improve codebase reliability and security by eliminating known bugs, replacing broad exception handling, hardening SQL construction, and fixing performance bottlenecks — without changing external behavior.

## v1 Requirements (All Complete)

### Bug Fixes

- [x] **BUG-01**: Nested `httpx.Timeout(timeout=httpx.Timeout(...))` in `app_front.py` is flattened to `httpx.Timeout(4 * 60.0)` — Phase 1

### Security

- [x] **SEC-01**: Database connection URLs use `SQLAlchemy URL.create()` instead of string interpolation — Phase 1
- [x] **SEC-02**: All bare `except Exception` handlers are replaced with specific exception types across the codebase (~40+ instances) — Phases 2 & 3
- [x] **SEC-03**: File upload metadata is validated against a Pydantic schema before processing — Phase 1

### Tech Debt

- [x] **DEBT-01**: Health check endpoint reports LLM and VLM service availability — Phase 5
- [x] **DEBT-02**: Restore script stops execution and rolls back on critical failure — Phase 5
- [x] **DEBT-03**: Hydra configuration version is properly set without warning suppression — Phase 6
- [x] **DEBT-04**: Legacy partition prefix backward compatibility workaround is removed or marked deprecated with timeline — Phase 6

### Performance

- [x] **PERF-01**: Restore script uses async Ray actor calls instead of blocking `ray.get()` — Phase 4
- [x] **PERF-02**: Async loaders use non-blocking file I/O (aiofiles or thread pool executor) — Phase 4
